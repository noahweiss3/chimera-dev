# Chimera App Explorer

Systematically explore a web application and capture everything needed to reconstruct it. You are the exploration intelligence — you decide what to click, what to fill, what to capture, and when to ask the user for guidance.

## Setup Check

Before starting, verify tools are available:

```bash
node --version   # require 18+
which browse || echo "MISSING: run npm install -g browse"
browse status    # check if a session is active
```

If no browse session is active, tell the user:
> "No active browser session. Please run `browse open <url>` to navigate to the target app, then tell me to start exploring."

## Exploration Modes

Ask the user which mode to use:

- **safe** — Read-only exploration. Click navigation, open modals, view pages. Never submit forms or trigger mutations.
- **explore** — Cautious mutations. Fill and submit forms with fake test data, but skip any action classified as destructive (delete, remove, archive, etc.).

## Initialization

Once the user has an active browse session and has chosen a mode:

```bash
node skills/app-explorer/scripts/init.mjs --url <target-url> [--explore]
```

This creates the `.chimera/` output directory and starts network trace capture.

## Exploration Protocol

### State Tracking

Maintain these lists throughout the exploration. Update them after every page visit.

- **visited**: Set of normalized URLs you have already captured (strip query params and fragments for comparison)
- **queue**: URLs discovered but not yet visited
- **page_counter**: Integer starting at 0, increment for each new page captured
- **current_section**: The nav section you're currently exploring

Before navigating to any URL, check if its normalized form is in the visited set. If so, skip it unless the user explicitly asks to revisit.

Do not go deeper than 4 levels of sub-navigation unless the user asks you to.

### Phase 0 — Public Surface

Before the user authenticates:

1. Run `capture-page.mjs` on the current (unauthenticated) page:
   ```bash
   node skills/app-explorer/scripts/capture-page.mjs --id 000 --section public
   ```
2. Read the summary output. Navigate to any visible public pages (pricing, about, docs) and capture each one.
3. Find and capture the login/signup page. Note the form fields, OAuth providers, or magic link options.
4. Tell the user:
   > "I've mapped the public surface: [list pages found]. Now please log in via the browser. Tell me when you're ready."
5. Wait for the user to confirm they've logged in.
6. Run `browse get url` to confirm the URL has changed (indicating successful auth).

### Phase A — Reconnaissance

After authentication:

1. Capture the authenticated landing page:
   ```bash
   node skills/app-explorer/scripts/capture-page.mjs --id <next-id> --section dashboard --auth
   ```
2. Read the summary. Identify the primary navigation structure (sidebar, top nav, tabs).
3. Present the site map to the user:
   > "I found these sections: **[list navigation targets]**. Which should I explore? All of them, or specific ones?"
4. Wait for user response. Build the exploration queue from their selection.

### Phase B — Breadth-First Sweep

For each section in the queue:

1. Navigate to the section: `browse click <ref>` or `browse open <url>`
2. Wait for page load: `browse wait load`
3. Capture the page:
   ```bash
   node skills/app-explorer/scripts/capture-page.mjs --id <next-id> --section <name> --auth
   ```
4. Read the summary. If sub-navigation exists (tabs, sub-menus), add those URLs to the queue.
5. Visit each sub-page within the section, capturing as you go.
6. After completing a section, report to the user:
   > "**[Section]** complete: [N] pages, [M] forms, [K] safe actions, [J] destructive actions found. Move to next section?"

### Phase C — Depth Exploration (explore mode only)

Skip this phase entirely in safe mode.

For each page that has forms:

1. Read the form structure from the capture output.
2. For each form field, determine appropriate test data:
   - Text/name: "Test Item" or "Sample Project"
   - Email: "test@chimera.dev"
   - URL: "https://example.com"
   - Number: "42"
   - Textarea: "This is test content generated by Chimera."
   - Select/dropdown: pick the first non-empty option
3. Fill the form using `browse fill`:
   ```bash
   browse fill "input[name=fieldname]" "test value"
   ```
4. Before submitting, check the submit button's classification from `elements.json`:
   - If **safe**: submit the form, capture the resulting network request/response
   - If **destructive**: DO NOT submit. Record it as a skipped action:
     Write to `.chimera/actions/skipped/<name>.json`:
     ```json
     {
       "page_ref": "<page-id>",
       "button_text": "<text>",
       "classification": "destructive",
       "reason": "Button classified as destructive. Skipped in explore mode.",
       "ref": "<element-ref>"
     }
     ```
   - If **unknown**: ask the user whether to proceed
5. For submitted actions, record in `.chimera/actions/submitted/<name>.json` with the request/response details observed in the browser.

### Phase D — Edge Cases

After completing all sections:

1. **Pagination**: On pages with tables or lists, look for "Next", "Load More", page number buttons. Note their existence but don't exhaustively paginate — capture the pattern.
2. **Modals**: Click non-navigation buttons to discover modal dialogs. Capture the modal content with `browse snapshot`.
3. **Search/filters**: If a page has search or filter controls, exercise them once to capture the interaction pattern.
4. **Empty states**: If you encountered pages with no data, note them — they often reveal create flows and empty-state UI.

## Finalization

When exploration is complete (all sections visited, user confirms):

```bash
node skills/app-explorer/scripts/finalize.mjs
```

Report the final summary to the user:
> "Exploration complete. Captured [N] pages, [M] forms, [K] API calls. Output saved to `.chimera/`. Ready for the next Chimera skill (api-mapper)."

## Important Rules

- **Never submit destructive actions.** Even in explore mode, delete/remove/archive/revoke actions are always skipped.
- **Always ask before exploring a new section.** Don't go rogue — the user steers.
- **Use capture-page.mjs for every page visit.** Don't manually run browse snapshot/screenshot — the script handles it and saves tokens.
- **Track your visited set.** SPAs with client-side routing can loop. Check before navigating.
- **Report after every section.** The user should always know what you found and what's next.
- **Prefer `browse snapshot` over `browse screenshot`** for understanding page structure. Screenshots are taken by capture-page.mjs automatically.
